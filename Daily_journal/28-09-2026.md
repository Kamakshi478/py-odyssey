# Decorators
  - definition- Python decorator is a function that take another function as an argument, extends or modifies its behaviour, and returns a new function without altering the original function's source code.'
  - Decorators leverage Python's first class functions (meaning functions can be passed around as arguments, nested and returned just like any other object) to enable clean reusable code.
  - They are commonly used for logging, authentication, caching and time execution.
  - A python decorator is like a gift wrapper for a function.
  - It is a tool that allows you to add new features or behaviour to an existing function without actually changing its original code.
  - Example: Think of it like adding sprinkles to an ice cream, or putting a security guard outside a building - the ice cream or building stays exactly the same,  but they now have extra features or protection.

## How wrapping works ?
  - In python , functions can be passed around just like variable.
  - A decorator is simple a function that takes your original function, wraps it inside an "inner" function adds some extra steps and then hands back to the modified version.
  -Instead of manually wrapping the function everytime, Python gives us clean shorthand using the @ symbol right above the function definition.

        def my_decorator(func):
        # This is the "gift wrap"
        def wrapper():
              print("🎁 1. Doing something BEFORE the function runs.")
              func()  # This calls your original function
              print("🎁 2. Doing something AFTER the function runs.")
           return wrapper

        # Applying the decorator using the '@' symbol
        @my_decorator
        def say_hello():
          print("   Hello, World! 😊")

        # Call the function
        say_hello()
## Output
 
    🎁 1. Doing something BEFORE the function runs.
     Hello, World! 😊
    🎁 2. Doing something AFTER the function runs.

## Real world uses cases 

  ### Logging and analytics
  - You want to log whenever specific functions are called to monitor what your application is doing.
  - Without decorators: You have to manually add print("Function X started) inside every single function.
  - with decorators: You write one @ log_activity  decorator and place it over any function you want to track.

### Timing and performance monitoring 
  - You want to measure exactly how long a function takes to run so you can find slow parts of your code.
  - how it works: The decorator records the start time, runs the function , records the end time  and prints out the total duration .

### Authentication and permission 
  - In web apps like, certain pages should only be visible to logged in users.
  - how it works: You can place a @login_required decorator above a web page function. The Decorator checks if the user is logged-in . If yes, it runs the function, if no it redirects them to login section.

### Caching and memorization
  - If a function does a heavy mathematical calculation or fetches the data from the internet, running it repeatedly with the same inputs slows down your app.
  - How it works: A @cache decorator remembers previous inputs and their results. If the function is called with a familiar input, it instantly hands back the saved result instead of recalculating it.
