# Collections 
  - Python's collections module provides specialized containers that make your code faster, cleaner, and easier to write compared to standard built-in data types

## Counter (The Tally Counter)
  - What it is: A specialized dictionary that automatically counts the frequency of items in a list or text.
  - Real-life example: Counting votes in an election or tallying up which fruits people bought at a grocery store (['apple', 'banana', 'apple'] becomes {'apple': 2, 'banana': 1}).
  - Why use it: Instead of writing a loop with messy if-else statements to check if an item exists, Counter does it instantly and gives you handy tools like .most_common(2)

## defaultdict (The Prepared Box)
  - What it is: A dictionary that doesn't crash with a KeyError if you ask for a key that doesn’t exist yet. Instead, it automatically creates that key with a default value (like an empty list or 0).
  - Real-life example: Organizing students by their grade. When you encounter a new grade for the first time, a normal dictionary throws an error. A defaultdict(list) automatically creates an empty list for that grade so you can add the student right away.
  - Why use it: It saves you from constantly writing if key not in dict: checks.

## namedtuple (The Labeled ID Card)
  - What it is: A tuple where you can access items using names (labels) instead of confusing numbers (indices).
  - Real-life example: Storing a GPS coordinate. Instead of remembering that index 0 is latitude and index 1 is longitude (location[0]), you write location.latitude and location.longitude.
  - Why use it: It makes your code self-explanatory and much easier to read without the heavy memory footprint of a full class

## deque (The Double-Ended Line)
  - What it is: Pronounced "deck", a double-ended queue. It lets you add or remove items from both ends (the front and the back) super fast.
  - Real-life example: A ticket counter line where people can join at the back, but if someone changes their mind, they can also leave from the front or the back instantly. Standard Python lists are slow when you remove items from the very front because every other item has to shift over.
  - Why use it: Operations at both ends take constant time, making it ideal for real-time queues and browser history (back/forward buttons)
