# Debugging 
## Post- Mortem debugging (Terminal)
  - If your scirpt crashes with an exception and you want to inspet what went wrong at the exact moment of failure, you can run your script module-style through the Python Debugger(pdb).

           python -m pdb my_script.py
  - If the script throws an unhandled exception, pdb will atoumatically  catch it and let inspect the variables right before the crash.

## Visual Debugging in IDEs (recommended)
  - If you prefer a graphical user interface over the command line, modern integrated development Environments (IDEs) make debugging visually intuitive.
  - Setting a breakpoint: click just left of the line number (adds or red dot).
  - How to start: open the "Run and Debug" tab (ctrl+ shift+ D) and click Run and Debug.
  - Inspecting state: view the locals pane to the left side or hover over varailbles.
  - Live evaluation: Use the debug console to run live python statements against the paused app .

## Advanced: conditional breakpoints 
  - Sometimes a bug only happens on the 500th iteration of a loop.
  - Stopping manually everytime is impossible.
  - Both VS code and and Pycharm allows you to to right-click a visual breakpoint dot and add a condition.

# Reading traceback 
  - A traceback is Python's way of showing you a map of what went wrong when an unhandled error occurs.
  - It displays the sequence of function calls that led to up to the crash, ending with the exact error name and message.
  - The secret to reading a traceback efficiently is to read it from the bottom up.

## Anatomy of a Python Traceback 

     Traceback (most recent call last):
      File "app.py", line 12, in <module>
      process_user_data(105)
      File "app.py", line 5, in process_user_data
    formatted_name = user_info['name'].title()
    KeyError: 'name'


### The very bottom line("The What")
  - Always starts here. It gives you the Error Type and a brief explanation
  - KeyError: 'name' means your code tried to look up a key called 'name' inside a dictionary, but that key does not exist .
### The line just above it (The "Where") 
  - Move one level up to see the exact line of code that triggered the error .
  - formatted_name = user_info['name'].title() is the exact statement that failed.

### The file & line info(The"Which File")
  - Just above the code line, Python gives you the file name and line number.
