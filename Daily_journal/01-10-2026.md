# Context Managers 
  - A context manager in Python is a tool that helps you manage resources automatically.
  -  Its main job is to handle the setup and cleanup of a resource for you, ensuring that the cleanup happens even if your code crashes.

    with open("file.txt", "w") as f:
    f.write("Hello")
    # The file closes automatically here, even if an error happens inside!

# How to Build Your Own (The __enter__ and __exit__ Methods)
  - To make a custom context manager using a class, you just need to add two special methods to it:
  - 1. __enter__: This runs before the code block inside the with statement starts. It sets up the resource and usually returns it.
  - 2. __exit__: This runs after the code block finishes (or if it crashes). It cleans up the resource.

## A Simple Example: A Custom File Opener
  - Here is how you can build a simple version of Python's built-in file opener:

        class CustomFileOpener:
         def __init__(self, filename, mode):
          self.filename = filename
          self.mode = mode

        def __enter__(self):
        print("🛠️ Setup: Opening the file...")
        self.file = open(self.filename, self.mode)
        return self.file  # This is what goes into the 'as' variable

        def __exit__(self, exc_type, exc_value, traceback):
        print("🧹 Cleanup: Closing the file...")
        self.file.close()
        # Returning None (or False) lets any errors bubble up normally

## How to use it ?

    with CustomFileOpener("test.txt", "w") as my_file:
         my_file.write("Writing some data!")
         print("📝 Inside the 'with' block: Just wrote to the file.")

    print("🏁 Outside the 'with' block.")

## Output
  - Setup: Opening the file...
  - Inside the 'with' block: Just wrote to the file.
  - Cleanup: Closing the file...
  - Outside the 'with' block.

## Understanding the __exit__ Parameters
  - If your code runs without errors, these three parameters will all be None.
  - If your code crashes, Python automatically passes the error details into these parameters. This allows your context manager to close resources safely even during a crash.


# Type hints
  - They are data labels: Just like stick-on labels on kitchen jars ("Sugar", "Salt"), type hints tell you exactly what kind of data is supposed to go into a variable or function.
  - They are completely optional: Python does not require them to run. They are extra notes written by the programmer to make the code easier to read.
  - They do not change how code runs: Python will not physically stop your program from running if you put the wrong data type into a labeled variable.

## Why should we use them ?
  - No more guessing games: You and your teammates don't have to guess whether a function needs a text string, a whole number, or a decimal.
  - Fewer bugs and mistakes: Your code editor (like VS Code or PyCharm) reads these hints and will highlight mistakes in red before you even run the code.
  - Better auto-complete: Because your editor knows what the data is, it can automatically suggest useful tools and options as you type.

## The core symbol
  - The Colon (:): Used to label a variable or a function input.
  - The Arrow (->): Used to label what a function sends back (the return value) at the very end.

##  Everyday Basic Labels
  - str (String) → Used for text.

   Example: username: str = "Alex"
  - int (Integer) → Used for whole numbers.
	 
   Example: user_age: int = 28
  - float → Used for numbers with decimals.
	
   Example: item_price: float = 49.99
  - bool (Boolean) → Used for True or False choices.
	
   Example: is_active: bool = True

## Advanced Labels (The typing module)
  - When dealing with collections of items, Python uses standard structures or imports specialized tools from its built-in typing module:
  - list → A list holding a specific type of item.
	  - Example: guest_list: list[str] = ["Alice", "Bob"]
  - dict → A dictionary with specific key and value pairs.
	  -  Example: prices: dict[str, float] = {"Apple": 1.50, "Banana": 0.99}
  -  The Pipe symbol (|) → Used when a value can be more than one type (e.g., text or a whole number).
	  -  Example: id_code: str | int = 404
