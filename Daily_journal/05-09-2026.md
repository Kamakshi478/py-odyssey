# Encapsulation 
  - Encapsulation is like a capsule or a protective shield around your code.
  - It means wrapping your data (variables) and actions (methods) together into a single package (a class) and hiding the internal details from outside the world.

## How it works in Python ?
Python doesn't lock things down completely, but it uses a naming system to tell the other programmer how to handle the data:
  - Public(open to everyone): anyone can look at it or change it.-> code: self.name 
  - Protected(Family only): A polite warning saying " Please don't touch this unless you are a part of this class or its children".-> code: sel._low_fuel_light
  - Private(strictly locked): Python actively hides this. if someone tries to look at it from the outside, Python will throw an error. code: self._blank_vault(starts with two underscores)

## Example 

    class PiggyBank:
        def __init__(self):
            self.__money = 0  # Private! Nobody can touch this directly.

    # This is the only official way to add money
    def add_money(self, amount):
        if amount > 0:
            self.__money += amount
        else:
            print("You can't add negative money!")

    # This is the only official way to check the balance
    def check_balance(self):
        return self.__money

    # --- Using the Piggy Bank ---
     my_bank = PiggyBank()

    # Trying to cheat and change the money directly will fail:
    # my_bank.__money = 1000000  <-- This causes an error!

    # You have to use the official buttons:
     my_bank.add_money(50)
    print(my_bank.check_balance())  # Output: 50

## Why do we do this ?
  - control: You decide exactly how people change your data (like blocking negative money).
  - safety: It stops people from accidentally breaking your code.
  - Simplicity: the person using your code doesn't need to know how the inside works, they just need to know what button to press.
