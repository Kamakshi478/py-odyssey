# Logging 
  - The logging module in Python is a built-in tool that records events, errors, and status messages while your program runs.
  - Think of it as a black box flight recorder for your code.
  - Instead of printing messages to the screen and losing them when the console closes, logging writes structured records to files, databases, or terminal streams so you can track down bugs later.

##  Why Use Logging Instead of print()? 
While print() is easy for quick debugging, it falls short in real-world applications for four major reasons:
  - Permanence: print() statement outputs disappear when the terminal closes. Logs can be saved permanently to files.
  - Granularity: You cannot easily turn off specific print() statements. With logging, you can instantly change how much detail you see across the entire application by changing a single configuration setting.
  - Metadata: Logging automatically includes critical context like the exact time, the filename, the line number, and the severity level of the event.
  - Routing: You can send logs to multiple places simultaneously (e.g., show severe errors on the screen, save detailed steps to a file, and email critical failures to an administrator).

## The Four Building Blocks of Logging
The architecture of the logging module relies on four main components working together:
  - Loggers: The entry point exposed directly to your application code. You call methods on loggers (like logger.info()) to trigger log events.
  - Handlers: The destination managers. They take the log record from the Logger and send it to the right place (e.g., StreamHandler sends to the console, FileHandler writes to a text file). A single logger can have multiple handlers.
  - Formatters: The layout designers. They specify the exact structure and text layout of the log message using attributes like time, level name, and message content.
  - Filters: The gatekeepers. They provide fine-grained control to determine which log records should be passed from a logger to a handler based on complex rules beyond simple severity levels.

## Best Practices 
  - Use __name__ for loggers: Always instantiate your loggers using logger = logging.getLogger(__name__) at the top of your modules to preserve clean tracking hierarchies.
  - Capture Exceptions Properly: Inside except blocks, use logger.exception("Message") instead of logger.error(). This automatically appends the entire traceback stack to your log, showing you the exact line of code that caused the crash.
  - Do not use string formatting manually: Avoid logger.info(f"User {name} logged in"). Instead, use logger.info("User %s logged in", name). This defers string formatting until the logger determines whether the message actually needs to be written, saving CPU cycles.
