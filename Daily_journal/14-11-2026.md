# Packaging 
  - Python packaging is the process of bundling your Python code into a neat, shareable format so you or others can easily install and reuse it across different projects.
  - eg:Think of it like turning loose recipe cards into a published cookbook that anyone can buy and use in their own kitchen.
  - In Python, code is organized in layers from small files to shareable bundles.

## What is a Package ?
  - Module: A single .py file containing Python functions, classes, or variables.
  - Package: A folder containing one or more .py files, along with a special __init__.py file that tells Python to treat the folder as a package.
  - Distribution Package: A compressed archive (usually a .whl or .tar.gz file) built from your code so it can be uploaded online or shared with others to install.

## pyproject.toml: The Project Blueprint
  - pyproject.toml is the modern, standard configuration file placed at the root of your project that describes your package and how to build it.
  - It replaced older files like setup.py and requirements.txt for defining project metadata.
  - A typical pyproject.toml file handles three main tasks.
  - Build System: Tells Python which tool (like setuptools, hatchling, or flit) should turn your folder of code into an installable package.
  - Project Metadata: Lists your package's name, version number, description, author details, and license.
  - Dependencies: Lists external libraries (like requests or pandas) that your package needs in order to work properly.
## Example code 

    [build-system]
    requires = ["setuptools>=61.0"]
    build-backend = "setuptools.build_meta"

    [project]
    name = "my-cool-tool"
    version = "0.1.0"
    description = "A simple tool that greets users"
    dependencies = [
    "requests>=2.28.0"
    ]


## pip: The Package Installer 
  - pip (which stands for "Pip Installs Packages") is Python's default tool for downloading and installing packages from the internet or your local computer.
