# Difference between compiler and Interpreter 
## Compiler                                                               
  - Translate the entire source code at once.
  - Faster because it runs pre-translated machine code.
  - Scans the whole program and list all the errors.
  - Generates a standalone executable file.
  - Higher memory needed to generate and store object code.
## Interpreter
  - Translate and executes line by line.
  - Slower because translation happens at runtime.
  - Stops immediately when it hits the first error.
  - Does not generate any intermediate object code file.
  - Lower memory needed as no intermediate fie is stored.

# Programming Language 
  - Set of instruction used to build complex, standalone system.
  - Programming languages build software from scratch.
  - Compiled into binaries.
  - Runs independently.
  - Require heavy boilerplate structure.
  - For languages like c++ and c.
# Scripting language
  - Connect and  automate existing software
  - Interpreted line by line.
  - Need a host application runtime environment.
  - Scripting language favor short, punchy scripts.
  - For languages like python and java .
# Command prompt
  - Command line interpreter application available in windows operating system.
  - It translates types text commands into actions that the operating system can perform.
  - Text-based environment dating back to MS-DOS.
#  Power shell
  - It passes structured NET data objects between commands rather than flat ,plain text strings.
  - It acts as both a command line environment and a robust scripting language for complex tasks.
  - It works natively across windows, Linux and macOS to manage files ,cloud services and servers.
#  Virtual Environment 
  - It creates a self contained directory containing its own isolated set of software packages and dependencies.
  - It allows different projects to use different versions of the same library without messing up each other.
  - it keeps your main operating system clean by preventing global package installations from breaking system tools.
  - It tracks specific project requirements in a simple text file, making sharing and deployment across teams effortlessly.
