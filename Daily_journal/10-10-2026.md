# Enums 
  - A dataclass in Python is a shorthand way to create classes that exist mostly to store information.
  - Think of a standard Python class as a factory. Usually, you have to write a lot of repetitive code (called boilerplate) just to tell the factory how to accept data, how to display it, and how to compare it. Dataclasses act like an automation template—they automatically build those repetitive parts for you behind the scenes.
  - Think of an Enum as a strict, read-only menu of choices. Instead of using loose strings or numbers across your code—which are easy to mistype—you group these options together under a clear category name.

## 1. They prevent typos and mistakes
  - If you use strings for options (like "North", "South", "East", "West"), you might accidentally type "north" with a lowercase letter somewhere in your code, causing a bug. With an Enum, you create defined choices (like Direction.NORTH).
  - If you mistype it, Python will immediately throw an error before your code even runs.

## 2. They make your code self-documenting
  - When someone else reads your code, seeing a function that requires a Status.PENDING object makes it immediately obvious what kind of input is expected, compared to a function that just asks for a random text string or a number like 1.

## code

    from enum import Enum

    class OrderStatus(Enum):
        PENDING = 1
        SHIPPED = 2
        DELIVERED = 3
        CANCELLED = 4

    # Using the Enum
    current_status = OrderStatus.PENDING

    if current_status == OrderStatus.PENDING:
    print("Your order is still processing.")

## When should you use them?
  - You should use an Enum whenever your program has a variable that can only ever be chosen from a fixed list of specific options. Common real-world examples include:
  - Days of the week (Monday to Sunday)
  - Compass directions (North, South, East, West)
  - User roles (Admin, Editor, Guest)
  - T-shirt sizes (Small, Medium, Large).



# Unit Testing 
  - Unit testing in Python is the practice of testing the smallest individual pieces of your code—usually a single function or method—in complete isolation to make sure it behaves exactly how you expect.
  - example:Think of your code like a car. Before you drive the fully assembled vehicle, you want to test the spark plugs, the battery, and the brakes individually to ensure each component works perfectly on its own. Unit testing does exactly that for your software.

## How it Works in Plain English
When you write a unit test, you write a short script that acts as an automated judge. It follows a simple three-step process:
  - Setup: It provides a specific input to your function (e.g., the numbers 3 and 5).
  - Execution: It runs the function.
  - Verification (Assert): It checks if the actual output matches your expected output (e.g., "Does it equal 8?"). If yes, the test passes. If no, it fails and tells you exactly what went wrong.

## Why is Unit Testing Important?
  - Catch bugs early: It is much easier to fix a bug when a specific unit test catches it instantly, rather than hunting for it later when the whole application crashes.
  - Fearless changes (Refactoring): If you want to rewrite a function to make it faster, you can do so safely. If your unit tests still pass after the rewrite, you know you didn't accidentally break anything.
  - Living documentation: Unit tests act as an instruction manual. Anyone reading your tests can immediately see exactly how your functions are supposed to behave under different conditions.
